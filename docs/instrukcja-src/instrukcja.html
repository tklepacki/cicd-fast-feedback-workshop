Przygotowanie do warsztatu

Szybki feedback w CI/CD: pipeline, który testuje i raportuje bez utraty jakości.

~30 minut 6 kroków Bez Javy i Dockera

Warsztat jest praktyczny — przez większość dnia będziesz pracować przy klawiaturze na własnym repozytorium. Żeby nie stracić pierwszej godziny na instalacje, wykonaj poniższe kroki przed warsztatem i sprawdź, że wszystko działa.

Przyjdź z laptopem, na którym masz uprawnienia do instalowania oprogramowania i dostęp do sieci bez blokad. Firmowy VPN albo polityki bezpieczeństwa potrafią zablokować npm lub GitHuba — sprawdź to zawczasu, nie rano na sali.

Nie potrzebujesz Javy ani Dockera. Jeśli brałeś udział w poprzedniej edycji tego warsztatu — tym razem pracujemy wyłącznie na GitHub Actions.

02Konto GitHub

Potrzebujesz prywatnego konta GitHub. Darmowe w zupełności wystarczy.

Jeśli masz konto firmowe objęte logowaniem SSO — użyj prywatnego. Firmowe polityki potrafią blokować tworzenie repozytoriów publicznych i uruchamianie workflow, a jedno i drugie jest nam dziś potrzebne.

03Własna kopia repozytorium

Otwórz repozytorium warsztatowe i kliknij zielony przycisk Use this template → Create a new repository.

PoleUstawienie
Repository namedowolna, np. warsztat-cicd
WidocznośćPublic
Include all brancheszaznacz

Zaznacz „Include all branches”. Bez tego nie dostaniesz branchy solution/* z rozwiązaniami ani demo/* z celowo zepsutym kodem — a używamy ich już w pierwszym zadaniu. To najczęściej pomijany krok w całej instrukcji.

Repozytorium musi być publiczne. Nie chodzi o dzielenie się kodem. Na darmowym koncie repozytorium publiczne dostaje nielimitowane minuty GitHub Actions i mocniejszy runner — cztery rdzenie zamiast dwóch. Na prywatnym część zadań jest technicznie niewykonalna.

04Klon i zależności

git clone <adres-Twojego-repozytorium>
cd <nazwa-katalogu>

npm ci
npx playwright install --with-deps chromium

Instalacja przeglądarki jest tym razem potrzebna — w warsztacie są testy UI, nie tylko API. Pobranie Chromium zajmuje chwilę, więc zrób to w domu, nie na sali.

05Sprawdzenie

npm run verify        # lint + typecheck + build + testy jednostkowe
npm run test:smoke    # 5 testów UI
npm run dev           # aplikacja: http://localhost:5173

npm run verify powinno zakończyć się bez błędów i wypisać 78 passed, a npm run test:smoke — 5 passed.

Aplikacja to prosty sklep: katalog, koszyk, zamówienie. Dokumentacja API czeka pod /api/docs po uruchomieniu npm start.

06Włącz GitHub Actions

Wejdź w swoje repozytorium → zakładka Actions. Jeśli zobaczysz komunikat o wyłączonych workflow, kliknij przycisk włączający je. Bez tego pierwsze zadanie nie ruszy.

  1. w zakładce Actions wybierz workflow CI,
  2. jeśli nie ma żadnego przebiegu — zrób dowolny commit i wypchnij go na main,
  3. poczekaj: przebieg powinien być zielony i trwać około czterech minut.

Te cztery minuty to nie błąd. To jest punkt wyjścia, który będziemy skracać przez cały dzień — i na koniec porównamy go z tym, co zbudujesz.
